# TextCore / 文心 课程详情页优化指令

请基于当前文心 TextCore 的高保真原型风格，重新优化“课程详情页 / 长文阅读页”。这是一个本地网页应用，用来把 3 万字左右的课堂转写 Word 生成三种版本：保真清洗版、学习整理版、结构提纲版。

## 当前页面问题

1. 不同课稿之间的切换方式不清晰。用户应该能快速回到课稿列表，也可以切换上一篇 / 下一篇课稿，而不是把两个样例按钮放在正文顶部占据阅读注意力。
2. 课稿被拆成 C01、C02 等多个处理块，但分块目录只在页面上方。用户读到正文下方后，如果想跳到 C02 / C03，需要滚回顶部，体验很差。
3. 原文对照目前只是一个小开关，交互含义不够明确。需要设计一种“整理版阅读 / 原文对照阅读”的清晰模式。
4. 右侧常驻的“知识卡片 / 作文素材 / 复核”会挤压正文宽度，让长文更窄、更长；同时它和正文当前片段之间的关联关系不明显。
5. 详情页的核心应该是舒适阅读，辅助信息应按需打开，而不是常驻占位。

## 设计目标

- 让 3 万字长文可读、可跳转、可定位。
- 让用户随时知道自己在读哪个处理块。
- 让用户可以快速回到课稿列表，或切换上一篇 / 下一篇课稿。
- 让正文区域更宽，阅读更舒服。
- 将知识卡片、作文素材、复核标记改成“按需打开”的资源面板或抽屉。
- 资源面板应能体现和当前 C 段的关联，例如“当前片段相关卡片”“当前片段复核项”。
- 原文对照应变成明确的阅读模式，最好支持同一 C 段的左右对照。

## 推荐信息架构

页面顶部：

- 返回课稿列表。
- 上一篇 / 下一篇课稿。
- 课程标题、课型、原始文件、字数、处理块数量、复核数量。
- 导出 Word。

长文工具区：

- 处理指标：原文字数、处理块数量、本地处理耗时、AI 预计耗时。
- 视图控制：保真清洗版、学习整理版、结构提纲版、原文对照。
- 长文控制：紧凑浏览、回到第一段。
- 资源入口：知识卡片、作文素材、复核标记。
- 分块目录：C01-C09，可点击跳转，并在滚动时保持可见或提供悬浮目录。

正文区：

- 单栏宽正文，最大宽度建议 880-960px。
- 每个 C 段显示标题、片段编号、原段落范围、字数。
- 每个 C 段底部提供：上一段、回目录、下一段。
- 长文模式下不要让右侧栏长期挤压正文。

资源面板：

- 点击“知识卡片 / 作文素材 / 复核标记”后打开右侧抽屉或底部面板。
- 面板中标明“当前片段相关”与“全文相关”。
- 每条资源应能反向定位到正文对应 C 段。

原文对照：

- 建议使用左右分栏：左侧原始转写稿，右侧当前整理版本。
- 对照应按 C 段同步，而不是把整篇原文和整篇整理稿一次性硬塞。
- 对照模式下可以隐藏资源面板入口，优先保证两栏宽度。

## 视觉风格约束

- 保持当前东方文字气质、纸本感、红色品牌色、克制温暖的界面。
- 不要做营销页，不要做大 hero。
- 不要使用过多装饰。
- 卡片圆角保持克制，8px 左右。
- 正文阅读优先，辅助信息降低视觉权重。
- 字体层级清晰：课程标题大，正文舒适，工具信息小而稳。

## 输出要求

请输出一版课程详情页高保真设计图，重点体现：

- 顶部返回和课稿切换。
- 长文分块导航常驻或悬浮。
- 更宽的正文阅读区。
- 资源面板从右侧常驻改成按需打开。
- 原文对照模式的布局。
- 手机端阅读时的分块导航和资源入口如何处理。
