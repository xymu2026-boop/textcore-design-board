# INBOX · Codex · 前端高保真还原（对照 demo 原型，自行浏览改进）

## 一、背景与原因（先读懂为什么做这件事）

文心 TextCore 是一个本地网页应用：妈妈上传课堂转写 Word，系统用 AI 清洗成四档浓度的学习资料（保真清洗/精简整理/学习整理/结构提纲）+ 知识卡片 + 作文素材 + 古文旁征博引 + 复核标记，可导出 Word。

项目早期做过一版**高保真可点击 HTML 原型（demo）**，视觉、排版、阅读体验都打磨得比较到位，是设计的"黄金标准"。后来正式开发时，前端从这个 HTML demo **迁移成了 React 应用**（`apps/web`），功能和数据流都接通了（真实后端 API、四档版本、卡片、古文、导出都能跑），**但视觉还原度不够**——用户反馈"跟之前的 demo 长得很不一样、精致度差了很多"，尤其是**课程详情页（长文阅读页）**的排版质感、间距、阅读区版式、古文引用块、复核标记样式，都比原型简单、粗糙。

虽然已经做过一轮初步还原（三栏布局已恢复），但用户希望你**自己打开 demo 和当前 React 应用，逐页仔细对比，把视觉精致度真正拉回 demo 水准**。你有浏览器插件，可以直接打开两个页面截图对比，请充分利用。

## 三、逐页还原要求

对照 demo，重点还原这几个页面/区块的**视觉与排版**（配色、字号、行距、间距、圆角、阴影、卡片质感、按钮样式）：

1. **工作台（首页）**
   - 左侧上传卡片（拖拽区、图标、主副标题、"选择 Word 文件"按钮）的尺寸、留白、质感。
   - 右侧处理进度步骤列表、最近处理历史表格的版式。

2. **课稿库（列表页）**
   - 表格行高、列对齐、状态徽标（已完成/处理中/有复核）、筛选区、搜索框样式。

3. **课程详情页（重点，长文阅读体验）** ← demo 在这页最讲究，差距也最大
   - 整体三栏：左浮动章节目录 / 中正文阅读区 / 右资源栏，宽度比例与 demo 一致。
   - **正文阅读区**：最大宽度、行距、字号、段间距、标题层级样式——要有舒适的长文阅读质感。
   - 课程摘要卡、四档版本切换 tab 的样式。
   - 原文对照视图的排版。
   - **古文旁征博引块**：原文 / 译文 / 字词注释 / 赏析 / 来源 的排版层次（demo 里这块有专门样式）。
   - **复核标记**：灰色低干扰下划线/括注，hover 效果，不要刺眼红色。
   - 右侧知识卡片 / 作文素材卡片、抽屉（drawer）面板的样式。

4. **知识资产库**
   - 卡片网格布局、卡片内字段排版、二级 Tab 样式。

5. **全局**
   - 顶部导航栏（Logo、页签、本地运行状态）、导出 Word 弹窗（modal）、按钮/标签/徽标的统一视觉语言。

## 四、硬性边界（不可越界，否则会破坏已冻结的系统）

- **只改 `apps/web/`**（前端）。
- **不要改** `docs/prototype/`（黄金参照，只读）。
- **不要动** `apps/api/`、`textcore/`、`schemas/`、`prompts/`、数据契约——后端与数据结构已冻结，改了前后端就对不上。
- **不要改数据流/接口契约**：API 基址 `http://127.0.0.1:8000`，端点 list/upload/detail/events(SSE)/export 保持不变。
- 四档版本 key 固定为 `faithful`/`concise`/`study`/`outline`，中文显示名映射为 保真清洗/精简整理/学习整理/结构提纲，默认打开 `concise`。**只能改显示样式，不能改 key。**
- 功能不许回退：列表加载、上传、处理进度、四档切换、抽屉、导出弹窗都要照常工作。
