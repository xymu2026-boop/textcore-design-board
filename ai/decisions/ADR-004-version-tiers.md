# ADR-004：版本档位与命名

- 状态：已采纳（2026-06-10）
- 决策人：Claude（架构）+ 用户授权（"四档，跟随 demo"）

## 决策

版本 = **四档**，跟随前端 demo。各档含义、默认档、压缩率如下：

| 内部 key（代码稳定） | 显示名 | 大致压缩率 | 角色 |
| --- | --- | --- | --- |
| `faithful` | 保真清洗 | ≈90%（65–90%） | 对照原文、保留课堂感 |
| `concise` | 精简整理 | ≈31%（30–35%） | **默认展示档**，给妈妈看的可读笔记 |
| `study` | 学习整理 | ≈9%（8–15%） | 更浓缩的要点版 |
| `outline` | 结构提纲 | ≈5%（5–10%） | 最浓缩框架，驱动目录 |

- **默认打开档 = `concise`（精简整理）**。

## 关键架构决策：key 与显示名解耦

代码、Schema、数据库、prompt **一律用英文 key**（`faithful/concise/study/outline`）。
中文显示名只存在于前端一张映射表 + prompt 模板里。

理由：四档后"学习整理"语义发生了漂移（从原产品定义的"默认可读版 25–45%"变成了"更浓缩的 9% 版"），
中文名也可能反直觉（"精简"听起来比"学习"省，实际更详细）。用英文 key 解耦后，
**未来任何改名只改一处显示映射，不触碰 Schema / 代码 / 已存数据**。

## 遗留与后续

1. **产品定义 v0.2 §9 已过时**（它定义的是三档、且"学习整理版"是默认 25–45% 版）。
   需同步改写，以本 ADR 四档语义为准。
2. **命名是否反直觉**：保留四档显示名进 v1，待 Phase 7.5 真实验收时，
   用户看到真实内容后决定是否给"精简整理 / 学习整理"改名（非阻塞，改显示映射即可）。
